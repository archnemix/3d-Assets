# CharacterCreator standalone morph defaults

Pinned source revision: `852e48f316b90a0937234886630e4fb4cdfd1f78`. All twelve source GLBs have 92 mesh default morph weights of 1, including mutually exclusive pairs such as `weight_min` and `weight_max`. Standard GLB rendering applies them all simultaneously, producing severely distorted shapes. Original-source previews and rejection decisions are retained in `reports/rejected/clothing-creator-01/` and `reviews/clothing-creator-01.json`; original bytes are retrievable by the pinned source URLs and verified hashes in `models.json` and provenance.

The upstream [`web/character.js`](https://github.com/kblood/CharacterCreator/blob/852e48f316b90a0937234886630e4fb4cdfd1f78/web/character.js) applies slider-derived morph influences at runtime, rather than relying on the exported defaults. Zero weights represent the undeformed base mesh, **not** a claim that the upstream application uses a particular default character or that all body fits will work.

For the separately reviewed neutral-default derivatives, `reset_default_morph_weights` rewrites only mesh default weights from 1 to 0 in the GLB JSON. It rejects unexpected layouts and preserves the entire binary chunk byte-for-byte. The original download SHA256 and byte count are retained in the `downloads` record in `asset.json`; `provenance/neutral-morph-defaults.json` records the derivative SHA256, change, target count and binary hash. All skin, target deltas and images remain, but animation, retargeting and fit are not verified. Runtime shader tint/mask features of the original application are not automatically reproduced in ordinary GLB viewers. Each derivative must pass Khronos validation and visual review before publication.
